## Findings and integration changes

1. **High — legacy feeding bypasses physical-care authority.** The main-game callback in `src/features/home/executeMainGameContextAction.ts` invokes the existing backend `pet_interact('feed')` (`src/lib/backend/supabaseBackend.ts`, migration `20261125000700_unified_catalog_inventory_quality.sql`). It immediately consumes shared normal food and updates the pet when a client requests feeding. The new `pet_care_apply` bowl path is not connected to that caller. Its explicit `SERVER_AUTHORITY_REQUIRED` gate on `eat_food` and `drink_water` does **not** protect the legacy RPC. Before deploying physical care, retire or safely gate the legacy feed path server-side and replace it with an authoritative lifecycle; retain explicit compatibility for other MVP actions. Add direct-RPC bypass tests, not only UI tests.
2. **High — Mission 02/03 inventory integration is incomplete.** PR #4's original `aggregateSharedStacksV015` collapses quality to normal and ignores private stacks. The trial changes the live projection to preserve `(ownerScope, SKU, quality)` and filter private stacks to the current user; held identity now preserves scope. This is a trial fix, not a change to PR #4. The projection remains limited to the initial food allowlist and eight slots. Legacy feed only supports shared normal kibble; the trial refuses other stacks rather than debit a different one. Complete the unified catalog adapter and connect quality-aware consumption, transfer and gift without changing balance or fingerprint `7076075b`.
3. **Medium — held selection can resurrect.** `src/features/home/useHeldItemFromHotbar.ts` derives an empty held item when a stack disappears, but keeps `heldAnchor` in state. Reintroducing the same identity can select it again without new input. Clear the anchor on confirmed depletion, while preserving identity through slot compaction; regression-test refresh, disappearance, replenishment and map transition.
4. **Medium — overlapping actions and keyboard focus.** PR #4 relied on React busy state for synchronous duplicate inputs, and its Escape listener was disabled when the modal was open. The trial adds a synchronous in-flight ref and enables Escape even with an editable modal field focused; focused Playwright coverage passes. This only serializes a mounted client: server idempotency, cross-device races, unmount/reconnect and map transitions still require independent tests and authority.

The original PR #4 already uses contextual resolution and guards the current frame/map; this does not prove authority over remote position or every stale async transition. Treat mobile Chromium emulation as a regression check, not real iPhone validation.

## Existing contracts and boundaries for Grok

- Reuse `src/shared/petAdvanced/primitives/` (utility math, stabilization, memory, affordances and sandbox) and Neon configuration `src/shared/petLiving/petIntelligenceConfig.ts`. `petPrimitivesAdapter.ts` is a deterministic pre-integration fixture, not the final Advanced Pet authority. Consult `docs/pet/PET_AI_PRIMITIVES_HANDOVER.md`; replace the fixture through its contract and test behavior rather than rewriting the engine. `petLabSimulation.ts` is a lab simulation, not a persistent backend.
- Adoption/rename currently uses `pet_adopt_or_rename(world_id, name, expected_version, idempotency_key)`. Physical care exposes `pet_care_apply(world_id, pet_id, action, expected_version, scope, sku, quality, idempotency_key)`, returning `{bowl, pet}`. `fill_food` accepts shared or the caller's own scope, normal `pet_kibble_basic`, consumes one stack item and increments bowl version; `fill_water` fills the bowl. The other two action names are recognized but currently rejected with `SERVER_AUTHORITY_REQUIRED`. Receipt replay is actor/action/payload bound. Read migration 00800 for exact errors, constraints and grants before calling it; do not claim the client can perform an authoritative eat/drink.
- Design an authenticated server-owned simulation/authority and failover before enabling consumption. A client may send an intent, not assert arrival, feeding, affection or reward. Validate membership, action availability, authoritative position and reachability, expected versions and server time; atomically lock and update world → pet → bowl/inventory in one transaction. Enforce both retry idempotency and unique business action so different retry keys or two devices cannot consume a portion twice or add affection twice. Define recovery/lease epochs and fencing before permitting host failover. Do not derive authority from Realtime messages or client clocks.
- Persist bounded memory and caregiver attribution in an authoritative transaction only after confirmed events; define storage, retention, reconciliation and failover before use. No current test proves persistent Advanced Pet memory or multiplayer authority.
- `src/game/pet/PetAnimationController.ts` maps behavioral intents including idle, move, eat, drink and petting to locomotion/animation; `src/game/entities/PetEntity.ts` renders the result. Keep animation visual only: an eat animation is not proof of inventory consumption. Preserve existing facing hysteresis, wake transition and Demo E artwork. Deliver state changes only from committed authoritative outcomes.
- Test adoption, filled/empty/full bowls, refusal/no appetite, water, stale versions, outsider/private scopes, quality identity, same/different idempotency keys, concurrent clients, lost response/retry, reconnect and authority failover. Test direct RPC access, not just React controls. Physical care currently lacks server position authority and the real server-side lifecycle.
